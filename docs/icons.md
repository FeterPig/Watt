# Watt icons and Segoe Fluent Icons glyphs

Everything in this document was generated and visually verified on the build machine
(Windows 11 build 26300, .NET Framework 4.8, no NuGet). No font files or NuGet packages are
shipped with the app: the panel renders glyphs with the system `Segoe Fluent Icons` font, and the
tray/app icons are self-contained bitmaps generated by `watt/tools/IconGen`.

## 1. Deliverables

| File | Frames | Use |
| --- | --- | --- |
| `watt/assets/tray-light.ico` | 16, 20, 24, 32, 40, 48 px | Tray icon on a **light** taskbar - pure black line art, transparent background |
| `watt/assets/tray-dark.ico` | 16, 20, 24, 32, 40, 48 px | Tray icon on a **dark** taskbar - pure white line art, transparent background |
| `watt/assets/Watt.ico` | 16, 20, 24, 32, 40, 48, 64, 256 px (256 = PNG frame) | Executable / Start / Explorer icon - blue rounded tile with white line-art mark |
| `watt/assets/previews/*.png` | - | Review PNGs (contact sheets, real-size strips, pixel zooms, ICO round-trip) |

The 16/20/24/32/40/48 px frames cover 100 %/125 %/150 %/200 %/250 %/300 % display scaling.
`Watt.ico` is already picked up by `Watt.csproj` via
`<ApplicationIcon Condition="Exists('..\..\assets\Watt.ico')">..\..\assets\Watt.ico</ApplicationIcon>`.
The two tray `.ico` files are meant to be embedded as resources and selected by the tray code
according to the taskbar theme (`SystemUsesLightTheme`).

## 2. Artwork

The tray mark is a minimal, natively-styled battery: rounded-rectangle body + terminal nub +
two level ticks, drawn on a **16 x 16 unit design grid** and rendered from vectors at every output
size (no downscaled-from-256 mushiness).

* stroke 1.5 units (= 1.5 px at 16 px, 3 px at 32 px), round caps and round joins;
* geometry is aligned so a 1.5 px stroke at 16 px produces one fully covered pixel plus one
  half-covered pixel - the sharpest possible 1.5 px line on a 16 px grid;
* ink is exactly `#000000` (light taskbar) / `#FFFFFF` (dark taskbar); antialiasing lives only in
  the alpha channel (audited, see section 6);
* fully transparent background; no gradient, no text, no color;
* ticks leave a 1 px clear gap to the outline so the mark does not turn into a solid blob at 16 px.

The app icon uses the same mark on a solid rounded-square tile: 256 x 256 design grid, tile inset
16, tile radius 52, Windows 11 accent blue `#0F6CBD`, white mark scaled 10.6 x the 16-unit grid
(≈ 62 % of the tile width, so the mark survives at 16 px in Explorer/Start). A flat tile - no
gradient - was chosen over a black tile because it stays recognizable on both light and dark
backgrounds (black tiles disappear into the dark-mode surface).

## 3. Regenerating (reproducible, offline)

Run from the workspace root (`watt\..`):

```cmd
dotnet build watt\tools\IconGen\IconGen.csproj -c Release
watt\tools\IconGen\bin\Release\net48\IconGen.exe all
```

`IconGen.exe` modes:

| Mode | Output |
| --- | --- |
| `glyphs` | `previews/glyphs-large.png`, `previews/glyphs-zoom-20px.png`, `previews/glyphs-chosen-20px.png` |
| `candidates` | `previews/art-candidates.png`, `previews/art-app-tiles.png` |
| `icons` | the three `.ico` files + all tray/app previews |
| `all` (default) | everything above |

The tool writes the icons relative to the workspace it is run from (it searches upwards for
`watt/src/Watt/Watt.csproj`), so it works from any current directory. Its own build output stays
inside `watt/tools/IconGen/bin|obj`.

To change the artwork, edit `Art.cs` (`TrayVariant`, `AppVariant`, tile colour, mark geometry,
`AppMarkScale`) and run the `candidates` mode first - it renders every variant at real 16 px on
light/dark taskbars plus 6x pixel zooms.

## 4. How the bitmaps are made

* **Rendering:** WPF `RenderTargetBitmap` with a `DrawingVisual`, 8x supersampling for sizes
  < 64 px and 4x for 128/256 px; a box filter then averages the supersampled pixels and converts
  premultiplied alpha to straight alpha, so 16 px gets the same shape quality as larger sizes.
* **ICO writer:** `IcoWriter.cs` emits a classic icon container - 32 bpp `BITMAPINFOHEADER` frames
  (with a correct AND mask, transparent pixels marked) for sizes ≤ 64 px and a PNG-compressed frame
  for 256 px, as required by Explorer/Start. Nothing is NuGet-dependent; the PNG encoder is WPF.
* **Self-check:** after writing, each `.ico` is decoded again with `IconBitmapDecoder`, frame
  sizes/counts are asserted, and every tray frame is audited for pure ink (section 6). The decoded
  frames are what `previews/tray-ico-frames.png` shows.

## 5. Segoe Fluent Icons glyphs used by the panel

Source: Windows 11 system font `Segoe Fluent Icons` (`C:\Windows\Fonts\SegoeIcons.ttf`, family
name "Segoe Fluent Icons"). Each candidate was rendered with WPF at the panel's real 20 px
`FontSize` on the exact light `#FFFFFF` and dark `#1D1D20` panel surfaces and inspected as a 4x
pixel zoom (`previews/glyphs-large.png`, `previews/glyphs-zoom-20px.png`). Verified values in
`watt/src/Watt/UI/Glyphs.cs`:

| Constant | Code point | Glyph name | Verification note |
| --- | --- | --- | --- |
| `Keyboard` | `U+E92E` | KeyboardStandard | Clearest keyboard at 20 px; `E765` KeyboardClassic is busier (more key dots), `E763/E764` are half-keyboards, `E766` split, `E961` Input mixes keyboard+mouse. No change needed. |
| `Mouse` | `U+E962` | Mouse | Clean at 20 px. No change needed. |
| `Headphone` | `U+E7F6` | Headphone | Over-ear headphone outline, clean at 20 px. `E95B` Headset adds a mic boom (correct only for headsets); `ED30`-`ED33` are "headphone with volume waves". No change needed. |
| `Other` | `U+E772` | Devices | Laptop + phone stack reads as "a connected device" at 20 px. `E7F4/E975` are also multi-device glyphs but visually busier. No change needed. |
| `Bolt` | `U+E945` | LightningBolt | Reads as a bolt at 20 px. `EA93`/`EBAB` are battery-with-bolt glyphs, too detailed for an 11 px charging marker. No change needed. |
| `Bluetooth` | `U+E702` | Bluetooth | Clean at 20 px (the classic rune). No change needed. |
| `Battery` | `U+E83F` | Battery10 | Generic full battery; `E850` is Battery0 (empty outline), `E85A` BatteryCharging0, `E996` BatteryUnknown. Kept `E83F` as the canonical "battery" glyph; the tray/app mark is custom vector art and does **not** use this glyph. No change needed. |

Rejected candidates: `E7E8` is the power-button glyph (not a battery), `E83D` renders as a generic
filled shape, `E704` is InternetSharing, `E703` Connect is a device-pairing glyph. `E972/E975` etc.
were probed on the contact sheet; none beat the current constants.

Note: the panel keeps `TextOptions.TextFormattingMode="Ideal"` and grayscale antialiasing, which is
exactly the rendering mode used for the verification sheets. The font is a Windows 11 system
component; do not ship `SegoeIcons.ttf` with the app (the panel falls back to a missing-glyph box
only on pre-Windows-11 machines, which the app does not target).

Pixel audit printed while generating the tray icons (same numbers for `tray-dark.ico`, with
`#FFFFFF` ink):

```
audit tray-light.ico 16 px: 104 ink px, 152 transparent px, non-pure ink = 0 (colour #000000, min alpha 6)
audit tray-light.ico 20 px: 162 ink px, 238 transparent px, non-pure ink = 0 (colour #000000, min alpha 3)
audit tray-light.ico 24 px: 194 ink px, 382 transparent px, non-pure ink = 0 (colour #000000, min alpha 2)
audit tray-light.ico 32 px: 292 ink px, 732 transparent px, non-pure ink = 0 (colour #000000, min alpha 21)
audit tray-light.ico 40 px: 524 ink px, 1076 transparent px, non-pure ink = 0 (colour #000000, min alpha 7)
audit tray-light.ico 48 px: 666 ink px, 1638 transparent px, non-pure ink = 0 (colour #000000, min alpha 1)
verify tray-light.ico: 6 frames [48, 24, 40, 32, 20, 16] all expected sizes OK
verify tray-dark.ico: 6 frames [48, 24, 40, 32, 20, 16] all expected sizes OK
```

`non-pure ink = 0` means every visible pixel is exactly `#000000` / `#FFFFFF`; the only variation is
per-pixel alpha from antialiasing (no grey halo, no color fringe). The generated tray icon therefore
matches the taskbar theme instead of carrying its own grey pixels.

## 7. Embedding notes for the app

* `Watt.ico` needs no code change - the existing `Watt.csproj` `ApplicationIcon` item picks it up and
  it also becomes the window/taskbar icon of the executable.
* Embed `tray-light.ico` and `tray-dark.ico` as `Resource` items (e.g. `/Assets/tray-light.ico`,
  `/Assets/tray-dark.ico`) or copy them next to the exe. Pick the frame that matches the current
  DPI and the ink matching `SystemUsesLightTheme`:
  * WinForms `NotifyIcon`: `new System.Drawing.Icon(stream, SystemInformation.SmallIconSize)` -
    System.Drawing picks the closest frame, and the 16/20/24 px frames are present for 100-150 %
    scaling (add `new Icon(icon, new Size(24, 24))` at 150 % if needed).
  * WPF/HwndSource shell notification area: decode with `IconBitmapDecoder` and choose the frame
    whose `PixelWidth` is closest to (`16 * dpiScale`). All frames are transparent-background and
    identical in shape, so any closest-size choice is safe.
* The panel needs nothing but the `FontFamily="Segoe Fluent Icons"` already used in `PanelView.xaml`
  and the verified code points in `Glyphs.cs`.
